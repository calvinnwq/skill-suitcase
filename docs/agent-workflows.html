06Operate · Agent workflows

Audit first, mutate on approval.

Agents run the read-only audit loop freely, report what they find, and cross a mutation boundary only after a human approves the exact source, target, and mode. The packaged operator skill encodes this loop.

The audit loop

skill-suitcase import --source "$SRC" --json
skill-suitcase validate --source "$SRC" --strict --json
skill-suitcase targets --source "$SRC" --json
skill-suitcase status --source "$SRC" --json

# then per target, with explicit path overrides
skill-suitcase status --source "$SRC" --target codex --codex-home "$HOME/.codex" --json
skill-suitcase diff --source "$SRC" --target codex --codex-home "$HOME/.codex" --json

Every command here is read-only. Repeat the same shape for claude, agents, and grok with their overrides. Treat read_only_target from provider-backed targets such as OpenCode and Pi as the expected boundary, not an error to work around.

The recovery decision tree

When a target does not match the catalog, the target state and ownership model select exactly one command:

a track The existing target exactly matches catalog source but has no receipt. Track writes the receipt and never rewrites skill files. Preview candidates with diff; track has no dry-run flag. b reconcile A receiptless target differs from a catalog-planned skill and catalog source should replace it. The prior target content is preserved as rollback state. c repair A receipt-owned copy install went dirty by accident and the catalog should win. Dirty means stop and inspect first; repair only after explicit approval. d prune A receipt-owned install is no longer assigned to the target. Dry-run returns a plan ID; apply repeats the exact skill list with that ID and quarantines directories transactionally. e promote A brand-new target-created skill should become catalog source. Promote copies it into the catalog and symlinks the original back to it. f import-target An intentional edit to a receipt-owned, catalog-owned skill should return to Git through review. The inverse of repair: it moves target content into the catalog.

Run the matching dry-run before reconcile, repair, prune, promote, or import-target, and use receipt-backed rollback when a mutation needs to be reversed.

Drift audit and heartbeat

Heartbeat

Re-run status --json and diff --json periodically as the drift-audit heartbeat. Reporting drift is automatic; importing or overwriting it is not. Drift detection is never permission to mutate either side.

When a catalog-owned skill goes dirty in a writable target, stop and inspect. repair --dry-run previews discarding the edit; import-target --dry-run previews keeping it, reporting the receipt hash, catalog hash, target hash, and planned repo writes. Either apply runs only after explicit approval that names the outcome.

Fresh machine setup

New-machine setup installs from the skills repo through Suitcase:

  1. Install skill-suitcase and the packaged operator skill.
  2. Clone or update the approved skills catalog at any local path.
  3. Run import, strict validate, targets, plan, status, and diff.
  4. Stage or lock the reviewed plan.
  5. Apply only the approved target changes and verify receipts and status.

The catalog-only upstream lane may refresh selected reviewed source before this flow, but it is not a shortcut for writing into live agent homes.

Verify and report

skill-suitcase status --source "$SRC" --json

Finish every session by reporting the catalog branch and SHA, the target IDs inspected, any live mutations run, final summary counts, receipt or backup paths, and anything skipped. Keep secrets, tokens, and private prompts out of chat, issues, and logs.

The step-by-step runbook version of this page is INSTALL.md; the packaged operator skill teaches the same loop to the agent itself.
